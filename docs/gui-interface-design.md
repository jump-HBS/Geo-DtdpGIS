# DtdpGIS GUI 界面结构设计

- 日期：2026-10-17
- 状态：待用户确认
- 配套原型：`docs/gui-mockup.html`

## 1. 设计目标

GUI 是通用批处理工作台，不硬编码 M1-M7 业务逻辑。它根据 `ToolSpec` 自动生成工具树、参数表单和结果视图，使后续新增工具不需要改 GUI。

## 2. 视觉基调

参考 51WORLD 数字孪生产品的深色科技工作台风格：

- 主背景使用深色中性色，信息区使用低对比面板。
- 强调色使用青色，状态色使用绿、黄、红。
- 不使用大面积单一蓝色或营销化渐变，保持专业工具感。
- 图标和文字结合，状态不只依赖颜色。

## 3. 五区布局

```text
┌──────────────────────────────────────────────────────────┐
│ 菜单栏：项目 | 工具 | 运行 | 视图 | 帮助                  │
├───────────────┬──────────────────────┬───────────────────┤
│ 项目工作区     │ 参数面板              │ 任务队列          │
│ 工具树        │ 动态表单 + 干跑/执行  │ 任务状态、日志    │
├───────────────┴──────────────────────┴───────────────────┤
│ 结果/报告：汇总 | 明细 | HTML 报告                        │
├──────────────────────────────────────────────────────────┤
│ 状态栏：run_id | 当前任务 | 项目 | 进度                   │
└──────────────────────────────────────────────────────────┘
```

## 4. 界面组件

### 4.1 菜单栏

菜单：项目、工具、运行、视图、帮助。

### 4.2 左侧：项目工作区与工具树

上半部分：

- 项目目录树：`inputs`、`outputs`、`quarantine`、`profiles`。

下半部分：

- 工具树按 M1-M7 分组。
- 叶子节点显示 `ToolSpec.name`，并携带 `tool_id`。
- M7 插件不可用时灰显，并显示原因。

### 4.3 中间：参数面板

- 根据 `ToolSpec.params` 动态生成。
- 目录、文件、数值、布尔、枚举、列表分别映射到对应控件。
- 提供干跑、执行、取消按钮。

### 4.4 右侧：任务队列

- 展示 `run_id`、工具名、状态、进度和日志。
- 支持取消、重试和断点续跑入口。

### 4.5 底部：结果与报告

- 汇总页：pass/warn/fail 计数和模块通过率。
- 明细页：统一 QC 长表，支持过滤。
- HTML 报告页：内嵌 L0 生成的报告。

## 5. 交互流

```text
选择工具 -> 填写参数 -> 干跑 -> 确认影响范围 -> 执行 -> 任务队列更新 -> 结果/报告更新
```

## 6. 核心 Qt 类结构

- `MainWindow`
- `ProjectWorkspacePanel`
- `ToolTreeBuilder`
- `ParamFormBuilder`
- `DryRunDialog`
- `TaskQueuePanel`
- `TaskQueueModel`
- `RunWorker`
- `ResultReportPanel`
- `ReportViewer`

## 7. 线程模型

GUI 线程只负责展示和参数收集。CPU 密集型工具通过 `ProcessPoolExecutor` 执行，任务状态通过信号槽回传。

## 8. 分阶段实现

1. P0：主窗口、项目工作区、工具树、参数面板，接 M1。
2. P1：任务队列、日志、取消、重试，接 M2-M3。
3. P2：结果三级视图和 HTML 报告，接 M4-M6。
4. P3：M7 插件树、可用性检查和 AI 结果摘要。

## 9. 两版布局方案

### 布局 A：流水线工作台

原型：`docs/gui-mockup-a.html`

特点：

- 顶部用 M1-M7 横向流程条表达数据处理阶段。
- 左侧保留项目资产树，中间是当前步骤的参数面板，右侧是任务队列。
- 底部结果区增加“数据流”标签，展示模块间的输入输出衔接。

适合：

- 强调 51WORLD 批处理流程和 M1-M7 数据传递。
- 适合向面试官或项目负责人演示完整处理链。

### 布局 B：模块工作台

原型：`docs/gui-mockup-b.html`

特点：

- 顶部使用 M1-M7 模块标签页，与 ArcGIS/QGIS 等 GIS 软件习惯接近。
- 左侧为资产目录，中间是模块内工具 chips 和参数面板，右侧为任务队列。
- 结果区直接显示当前模块的检查明细。

适合：

- 日常按模块处理数据，快速在工具之间切换。
- 更适合 GIS 工程师的高频操作习惯。

### 建议

1.0 建议采用 **布局 B** 作为默认布局，因为它是熟悉的模块工作台，学习成本低。

在项目初始化或演示流程时，可以切换到 **布局 A** 的流水线视图，用于展示 M1-M7 处理链和运行状态。

## 10. 浅色模块工作台三版方案

以下三版基于模块工作台优化，采用浅灰基底、低饱和青蓝色主色、白色卡片和 4-8px 圆角，模块名称不再显示 M1-M7 前缀。

### V1：左侧模块导航

原型：`docs/gui-mockup-b-v1.html`

- 左侧为功能模块导航，中间为工具卡片和参数表单，右侧为任务队列。
- 适合把模块作为一级导航、高频切换工具的场景。

### V2：顶部模块标签

原型：`docs/gui-mockup-b-v2.html`

- 顶部横向模块标签，左侧资产目录，中间参数面板，右侧任务队列。
- 最接近传统 GIS 桌面软件习惯，信息密度适中。

深色可切换版本：`docs/gui-mockup-b-v2-dark.html`，默认深色，可在顶部切换浅色/深色。

### V3：窄图标栏 + 面包屑

原型：`docs/gui-mockup-b-v3.html`

- 左侧收窄为图标栏，顶部使用面包屑定位模块和工具。
- 中央工作区更大，适合宽屏显示和长时间数据处理。

建议默认采用 V2，V1 适合模块主导的导航场景，V3 适合宽屏高效工作场景。
