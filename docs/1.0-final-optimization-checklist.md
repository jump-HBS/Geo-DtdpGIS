# DtdpGIS 1.0 最终优化清单

- 日期：2026-10-18
- 目标：把软件从“模块流程工具”调整为“可单独使用的数据处理工具集合”
- 状态：待逐项实施与验收

## 1. 核心方向

1. 所有数据处理工具都可以单独运行，不强制依赖 M1-M7 顺序。
2. 项目初始化和自动创建目录改为可选工作空间，不能阻塞工具使用。
3. GUI 前端要展示每个工具的结构化输出，而不是只显示简单的 pass/fail。
4. 保留 M1-M7 的数据处理能力和模块组织，只改变入口和交互方式。
5. 删除“干跑”模式，工具点击执行后直接运行。

## 2. 工作空间改造

### 2.1 不再强制创建项目

- 删除“打开软件必须选择项目并初始化运行”的限制。
- 软件启动后直接进入工具库。
- 用户可以选择数据文件或文件夹后直接运行工具。

### 2.2 工作空间改为可选加速入口

工作空间定义为：

```text
<用户选择的数据目录>
├─ 01_点云
├─ 02_矢量
├─ 03_栅格
├─ 04_倾斜摄影
├─ 05_CAD
├─ 99_其他
```

作用：

- 快速选择常用输入目录。
- 记住上次输出目录。
- 不自动创建 `outputs/quarantine/reports`。

## 3. 工具输入输出规则

每个工具默认支持：

```text
输入目录或文件 -> 执行 -> 输出到用户指定目录或输入目录旁的 <tool_id>_output
```

不再保留“干跑”按钮。

用户未选择工作空间时：

- 输出目录默认由用户选择。
- 如果用户没有选择输出目录，输出到输入数据同级目录下的 `<tool_id>_output`。

## 4. 前端状态与结果展示

### 4.1 顶部状态栏

显示：

- 当前工具名称。
- 当前输入路径。
- 当前输出路径。
- 运行状态：待执行、运行中、完成、失败、已取消。
- 运行耗时。

### 4.2 任务队列

显示：

- 工具名称。
- 开始时间。
- 状态。
- 处理文件数。
- 成功/警告/失败数量。

### 4.3 结果面板

分为四个标签页：

1. 汇总：成功、警告、失败数量，输出目录，耗时。
2. 文件明细：每个文件/资产的名称、格式、结论、详细信息。
3. QC 表格：读取 CSV 长表展示。
4. 输出文件：列出本次生成的 JSON、CSV、GPKG、TIF、LAS 等文件，支持双击打开所在目录。

## 6. 后端需要补强的能力

1. 所有工具返回结构化 `ToolResult`。
2. `ToolResult` 增加输出文件列表、耗时、输入路径、输出路径。
3. 所有 CSV/JSON 输出文件名统一，便于前端展示。
4. 所有工具在无工作空间时也能使用，不依赖 `RunContext.project_root`。
5. 输入文件不存在时返回明确错误。
6. 大文件默认不计算哈希，避免卡顿。
7. 支持取消、进度反馈和耗时统计。
8. 删除干跑、旧版工作流和不再使用的废弃代码。

3. 工具执行结果能在界面中查看。
4. 工作空间只作为可选快捷入口。
5. 无强制创建 `outputs/quarantine/reports`。
6. 测试数据源下所有工具均有真实数据验证记录。
